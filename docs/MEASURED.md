# 实测记录

> 每个被限程序一行一节,按时间倒序追加。环境:i5-14600KF 14C/20T,64GB,
> Windows 11,C:=SSD,F:=HDD 13T。**全部数字实测,不抄文档。**
> 选项语义按「全平台一致」设计;本页全部为 Windows 后端(Job Object)的实测。
> 选项速查与语义要点见 [README](README.md)。

## 汇总

| 程序 | 负载类型 | 生效的限制 | 备注 |
|---|---|---|---|
| burn(自带) | CPU 燃烧 | `--cpu` `--affinity` | 调度器级精确 |
| alloc(自带) | 逐 MB 分配 | `--mem` `--mem-total` | 撞顶即分配失败,1455 |
| diotest(自带) | 直写拷贝 | `--io` `--iops` | 直写/写穿透精确生效 |
| 7z | 解压(缓存写+吃 CPU) | `--cpu`(节流阀);`--io`/`--iops` 对缓存写不保证 | 小包线性减速;HDD 大包削峰 |
| robocopy | 批量拷贝(缓存写) | `--cpu` `--io` `--iops` 全部可压 | 小数据量时 `--io`/`--iops` 无感(全进缓存) |
| cmd | 进程树 | `--procs` | 孙进程创建被拒 |

## robocopy(Windows 拷贝,缓存写)

日期:2026-10-25。语料 17000 文件 / 660MB(C:→C:,SSD,默认缓存写)。

| 档位 | 耗时 | robocopy 报告速率 |
|---|---|---|
| 基线 | 6.3s | 112 MB/s |
| `--cpu 25%` | 9.6s | 73 MB/s |
| `--io 10` | 11.8s | 60 MB/s |
| `--iops 100` | 34.7s | 27 MB/s |
| `--iops 30` | 92.9s | 7.5 MB/s |

- 四类顶全部压得住,梯度与档位一致。
- **小数据量时 `--io`/`--iops` 无感**:78MB 同负载 `--io 10` 完全不减速——拷贝全进
  文件缓存,IO 限速 API 管不到回写。数据量上去(缓存压力)后才拉开差距。
- `--iops` 对 robocopy 很灵敏:每文件 create/read/write/close 全计数,30 IOPS
  压到 7.5MB/s(15 倍减速)。机械盘上给 robocopy 限速保交互,`--iops` 优于 `--io`。
- robocopy 退出码 1 =「有文件被拷贝」,是正常返回码,不是报错。

## 7z(解压,缓存写 + 吃 CPU)

日期:2026-10-24。两组负载。

**小包**:388MB → 396MB 输出,全部进文件缓存(回写未发生):

| 档位 | 耗时 |
|---|---|
| 基线 | 1.57s |
| `--cpu 10%` | 1.80s |
| `--cpu 5%` | 2.46s |
| `--cpu 2.5%` | 7.96s |

**大包**:2GB 压缩包 → 解压 7.5GB / 5.7 万文件到 F:(HDD),跑完整程:

- 基线全程 2130s ≈ 3.6MB/s;物理写入除开头外稳在 4MB/s(机械盘小文件底盘)。
- 开头有 61MB/s 的缓存回写爆发;`--cpu 5%` 把爆发削到 13MB/s,曲线全程平稳
  (`10%` 也有 62MB/s 突刺)。

结论:`--cpu` 是「全 IO 类型」节流阀,实际 IO 速率 ≈ min(磁盘自然速率, CPU 顶折算速率);
吞吐压无可压时(HDD 小文件),价值在削峰。

## 自带验证工具(tests/,C 写的,与限制器语言无关)

| 工具 | 测试 | 结果 |
|---|---|---|
| burn | `--cpu 5%` × 4 线程烧 10s | CPU 10.55s ≈ 正好 1 核(5% × 20 逻辑 CPU) |
| burn | `--cpu 10%` × 4 线程烧 6s | CPU 11.14s ≈ 2 核 |
| burn | `--cpu 25%` × 4 线程烧 6s | 与不限速基线无分布差异——5 核对 4 线程不触顶(上限高于需求时不生效) |
| burn | `--affinity 0x1` × 2 线程烧 6s | CPU 5.55s(绑 1 核) |
| alloc | `--mem 256M` 分配 1024MB | ALLOC_FAILED at 254MB,错误码 1455 `ERROR_COMMITMENT_LIMIT` |
| alloc | `--mem 512M --mem-total 700M` | 510MB 处失败(单进程顶先触发) |
| diotest | `--io 50` 直写拷贝 254MB | 10.07s(单向 26.5MB/s,读写合计 53MB/s ≈ 上限) |
| diotest | `--iops 100` × 300 次写穿透小 IO(4KB create+write+close) | 0.55s → 25.1s,压到 ≈100 操作/s(create/close 元数据也计数) |
| diotest | `--io 100 --iops 100` | API 接受双顶,IOPS 先撞顶生效 |
| diotest | `--io 50` 双盘并行(C→D 与 C→E,共 1016MB) | 各跑 17.2s/20.2s(合计 ≈50MB/s)——**`--io` 是整 Job 聚合配额,非按盘独立**(与微软文档不符,以实测为准) |
